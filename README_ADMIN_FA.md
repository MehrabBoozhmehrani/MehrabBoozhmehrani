# راه‌اندازی پنل مدیریت امن (Supabase + Vercel)

این نسخه برای ورود مدیر از Supabase Auth و برای ذخیره محتوای عمومی از Supabase Database استفاده می‌کند. رمز عبور مدیر داخل کد قرار نمی‌گیرد.

## ۱) ساخت پروژه Supabase

1. در [supabase.com](https://supabase.com) یک پروژه جدید بساز.
2. از بخش **Authentication → Users** یک کاربر با ایمیل `mehrabboozhmehrani30@gmail.com` و یک رمز قوی ایجاد کن. این حساب مدیر سایت است.
3. ثبت‌نام عمومی کاربران را در تنظیمات Authentication غیرفعال نگه دار؛ فرم ثبت‌نام عمومی در سایت وجود ندارد.
4. از **Project Settings → API** آدرس Project URL و کلید `anon` یا `publishable` را بردار.
5. فایل `supabase/setup.sql` را در **SQL Editor** اجرا کن. دستور پایانی فایل، کاربری با ایمیل بالا را به فهرست مدیران اضافه می‌کند. اگر ایمیل ورود دیگری انتخاب کردی، قبل از اجرا آن را در SQL عوض کن.

## ۲) تنظیم پروژه روی کامپیوتر

1. فایل `.env.example` را به `.env.local` کپی کن.
2. مقادیر واقعی Supabase را در این دو متغیر قرار بده:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. فقط کلید `anon` یا `publishable` را قرار بده. **هرگز `service_role` یا کلید secret را در متغیرهای VITE، کد فرانت‌اند یا Git قرار نده.**
4. در پوشه پروژه اجرا کن:

```powershell
npm install
npm run dev
```

## ۳) تنظیم Vercel

1. پروژه را به GitHub push کن و در Vercel از **Add New → Project** مخزن را Import کن.
2. در Vercel وارد **Project → Settings → Environment Variables** شو.
3. این دو متغیر را با همان مقادیر Supabase اضافه کن و برای Production (و در صورت نیاز Preview) فعال کن:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. ذخیره کن و از **Deployments → Redeploy** یک استقرار تازه انجام بده.

## ۴) استفاده از پنل

1. سایت را باز کن و روی «مدیریت / Admin» بزن.
2. با ایمیل مدیر و رمز عبوری که در Supabase ساخته‌ای وارد شو.
3. محتوای JSON را ویرایش و «ذخیره روی سایت» را بزن. اطلاعات در دیتابیس ذخیره می‌شود و برای همه بازدیدکنندگان به‌روزرسانی خواهد شد.

## نکات امنیتی مهم

- قابل مشاهده بودن دکمه ورود اشکالی ندارد؛ دسترسی نوشتن در دیتابیس با Row Level Security محدود شده است.
- صرفاً کاربرانی که شناسه آن‌ها در `portfolio_admins` ثبت شده، مجاز به ذخیره تغییرات هستند. ورود یک کاربر عادی به‌تنهایی دسترسی مدیریت نمی‌دهد.
- کلید `anon/publishable` برای استفاده در مرورگر طراحی شده و به‌تنهایی مجوز نوشتن نمی‌دهد؛ سیاست‌های RLS تعیین‌کننده‌اند.
- برای افزودن مدیر دیگر، ابتدا کاربر را در Supabase Auth بساز و سپس شناسه UUID او را در جدول `portfolio_admins` وارد کن. این کار را فقط از داشبورد امن Supabase انجام بده.
- فایل‌های مدارک فعلاً از پوشه `public/certificates` سرو می‌شوند و عمومی‌اند؛ این مناسب مدارک نمایشی پورتفولیو است، نه اسناد خصوصی.
